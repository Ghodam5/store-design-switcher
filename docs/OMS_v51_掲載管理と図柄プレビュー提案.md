# OMS 2.1とのサイト掲載管理・図柄プレビュー連携案

2026-11-20 林さん依頼。**提案のみ。本体を変更する前に確認する。**
対象は公開OMS `oms/luna_luce_oms_ui_v2.html`、本店と元DBは変更しない。

## 現状の確認
- 最新OMSは商品カタログJSONの読込み部分が追加されているが、サイトのお知らせ・休日・特集を公開する保存APIはまだない。
- `renderDrawerPreview` は固定の四角いSVGにmessage/couple/wedding/font/noshiを入れるだけ。miniSeal、templateId、SKU、productIdの参照は同関数内に0件。商品図柄を反映するプレビューではない。
- `renderDrawerSamples` も共通3スタイル。`PART_KEYS`にminiSealとthanksCardはあるが、図柄テンプレートへの紐付けがない。
- サンクスカードは提供終了の新指示。新規選択から非表示とするが、過去受注・BOMの内訳を一括削除してはならない。

## 提案する進め方
| 段階 | 操作と保存先 | 公開の扱い |
|---|---|---|
| 現在のGitHubサンプル | OMSの新しい独立した「サイト掲載管理」タブからJSONを書き出す | サイト担当が検査、プレビュー、コミット・公開。まだ自動公開ではない |
| 次の連携 | 管理用サーバーでJSON受付→GitHubの変更案／PR | CI合格と承認後に公開。トークンはサーバーだけに置く |
| WordPress本番 | 新WordPressを掲載設定の正本、OMSから専用APIへ保存 | 権限・版競合・下書き・承認・掲載期間とキャッシュをサーバーで管理 |

ブラウザのOMSや公開リポジトリへGitHubトークン・本店パスワードを入れない。既存本店のDBを掲載設定用に書換えない。WordPress/Welcartの対象版を確認してからAPIを実装する。現在存在しないAPIへの接続済み表示を作らない。

## サイト側で分離済みの設定
- 上部お知らせ：site-src/site-notices.json。schemaVersion=1、timeZone=Asia/Tokyo、notices[]。id、active、text、href、任意startsAt/endsAt（時差付きISO、日本時間表示、終了は含めない）。現在はビルド→次のページ読込みで反映、OMSからの自動公開は未接続。
- お知らせ本文：site-src/editorial/のnews。トップ帯の一言と本文は別項目。
- 営業日・休業日：site-src/site-settings.jsonのcalendar。既存の曜日設定／例外日を読み込んで変更する。古い固定日付を現行休業日と扱わない。
- 特集と掲載順：site-src/home-promos/、manifest.json、home-layout.json、ranking-top10.json。

## OMS担当に依頼する部品
既存HEADER_TABS/renderMain/mountOrderedの方式を使い、受注タブ全体を作り直さない。
1. `tab-site-content`：お知らせ・営業日・特集をそれぞれ独立した編集部品にする。現在値を読み込む→変更→プレビュー→検証→書き出し。draftRevision、公開版、更新者、更新日時を持つ。
2. JSON読込時は未知キー・不正URL・逆期間・重複IDを拒否。元ファイルを上書きせず新版を出す。接続未設定なら保存は「下書き書き出し」と表示する。
3. 商品・SKU・価格・在庫・注文は掲載設定に複製しない。名前や受注内容を公開用JSONへ入れない。

## ミニシール／名入れの共通契約
サイト側の `site-src/seal-preview-choices.json` はカートと同じ59図柄のid/label/cartValue/image/previewImageを保持。各画像は公開見本であり、製造原稿ではない。
- デザインマスタ：templateId、templateVersion、対象productId/SKU、designId、印刷可能範囲mm、用紙／面数、フォント、文字数、必須入力、原本ファイル、見本画像を紐付ける。
- 受注明細：lineId、本体との関連ID、選択designId、入力原文、templateVersion、確認／校正状態を保存。f0や画面の並び番号を恒久キーにしない。
- プレビューは明細ごとのテンプレートを選ぶ。未登録なら「図柄未登録・共通参考見本」と明示し、実製造に使えると表示しない。
- 元の個別画像は150〜230px程度。既存450px画像も細部の復元を保証しない。高精細化には元のAI/PDF/SVG等が必要。画像内の固定名を白塗りして入力名へ置換したように見せない。
- 席札・席次表は商品CSVで「手作り・テンプレート編集印刷」を確認。購入者用ダウンロード方式の既存調査あり。購入用テンプレートの再配布は行わず、汎用の入力配置見本と区別する。印刷用の余白・フォント・面付けの確定前に実寸PDFを製造へ回さない。

## AI間の受け渡しと競合防止
- 第二の脳06_AI同士の連絡に、作業対象・担当・版・依存・変更禁止箇所・受け入れ検査・コミットを記す。
- 着手前pull、00_作業中の札にファイル範囲を書く。OMS担当とサイト担当は同じファイルを同時に変更しない。共通契約JSONの変更は先に依頼票で通知。
- Cursor：OMSの独立タブと図柄アダプター。Codex：サイト表示・契約の検証・5幅QA。Claude：本店／バックアップとの図柄・文言・用紙の照合。これは提案する役割で、自動で各AIへ作業を発注済みではない。

## 共通の受け入れ検査
- JSON書出し→再読込で値が保たれる。別の版からの保存は競合として止める。失敗時は公開済み版を残す。
- 開始直前／開始／終了直前／終了（日本時間）、手動停止、タイムゾーン、端末時計ずれ、公開キャッシュ。
- 個人情報／注文／秘密鍵が公開JSONへ混入しない。料金や在庫を掲載文だけで上書きしない。
- 59図柄のID・カート値・画像一致、別明細の名前が混ざらない、古い注文は注文時のテンプレート版で再表示。
- 名入れOFF、最低数量未満、文字数超過、日付不正、旧字、画像未読込、原本不足、販売終了、過去のサンクスカード内訳。
- スマホ320/390/440/834、PC1280、横スワイプ、数量ホイール、連続タップとピンチ、印刷実寸／画面見本を別々に検査。
